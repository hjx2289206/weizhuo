# 棋类 AI

中国象棋、国际象棋、五子棋与黑白棋提供入门、简单、普通、困难、挑战五档。象棋和国际象棋通过原生引擎的降强选项和搜索预算调节难度。五子棋和黑白棋使用随服务运行的 TypeScript 搜索。档位表示各游戏内的相对难度，尚未做过人类 Elo 校准。

## 使用

首页先进入「棋类」，再点对应游戏标题旁的「人机对弈」，创建手机模式房间并打开难度设置。选好难度后准备、开始。也可在已有准备页点「人机对弈」。手机默认玩家先手，国际象棋执白、中国象棋执红、五子棋和黑白棋执黑。平板可选先手或后手，电脑先手时开局后自动走棋。

与电脑对弈时自己的阵地在下，棋子统一正向。电脑座位显示难度与思考状态；服务器和界面都会阻止玩家替电脑走棋或替电脑认输。断线时取消思考，恢复后对同一棋局重新计算。电脑异常保留棋盘并提供「重试电脑行棋」，不会跳过回合。

等电脑走完后点「悔棋」，直接退回到自己上一手之前，次数不限。重新行棋后电脑会按新局面应手。详见 [棋类悔棋](board-undo.md)。

本局结束后再开一局会保留难度，准备阶段可以调整或改回双人对弈。电脑只会占空座位，不能替换真人；电脑没有客户端凭证，不可获得房主权限，不能申请接替电脑座位。协议和棋供双人对弈使用，人机模式保留原有棋规自动和棋与玩家认输。

## 安装与版本

```bash
npm run setup:board-ai
npm run test:board-ai
# 安装完成后启动或重启服务
npm run dev
```

安装器只写项目 `.board-ai/`，目录已忽略且不进入前端构建。可通过 `BOARD_AI_DIR` 指定另一独立目录。已有文件通过 SHA256 验证后重用；单独安装支持 `npm run setup:board-ai -- --engine=stockfish`，需要重新构建时使用 `--force`。

| 游戏与档位 | 引擎与固定版本 | 网络 |
|---|---|---|
| 国际象棋五档 | [Stockfish sf_19](https://github.com/official-stockfish/Stockfish/releases/tag/sf_19) | 官方发行包内嵌 NNUE |
| 中国象棋前四档 | [Fairy-Stockfish](https://github.com/fairy-stockfish/Fairy-Stockfish) `9f778da667f6e07dae1e85d3e2ea204fc6dee94d` | `xiangqi-c07e94a5c7cb.nnue` |
| 中国象棋挑战 | [Pikafish-2026-09-06](https://github.com/official-pikafish/Pikafish/releases/tag/Pikafish-2026-09-06) | 发行包内的配套 `pikafish.nnue` |
| 五子棋、黑白棋五档 | 项目自研 TypeScript 搜索，随服务运行 | 无需外部引擎或模型 |

下载来源和归档校验固定在 `scripts/board-ai-setup.ts`。安装后的二进制、外部权重 SHA256、来源和版本记录在 `.board-ai/manifest.json`。启动时逐个校验并进行真实搜索；缺文件、哈希不符、架构错误、缺必要选项或 NNUE 无法加载时，该引擎对应的档位不可用。运行时检测到已校验文件变化也会禁用，须重启重新验证。

当前机器实测为 macOS ARM64。安装脚本也提供 macOS x64、Linux x64 路径；Fairy-Stockfish 需要 C++ 编译器和 make，Linux 解压皮卡鱼需 bsdtar 或 7z。Linux ARM64 可分别安装 Stockfish 与 Fairy-Stockfish，皮卡鱼需自行本机编译后登记清单；这些其他平台尚未实机验收。

## 原生引擎难度与搜索

| 难度 | Stockfish 技能级 | Fairy-Stockfish 技能级 | 节点上限 | 每手时间上限 |
|---|---:|---:|---:|---:|
| 入门 | 0 | -20 | 300 | 100 ms |
| 简单 | 3 | -8 | 1,500 | 180 ms |
| 普通 | 8 | 4 | 8,000 | 350 ms |
| 困难 | 14 | 14 | 40,000 | 750 ms |
| 挑战 | 20 | 此档使用皮卡鱼 | 150,000 | 1,500 ms |

节点与时间均为上限，先达到任一上限即可返回。每个进程 1 线程、32 MiB 搜索表，服务最多同时运行两个搜索进程，最多排队 32 个请求；排队也受房间 15 秒响应保护。强弱单调性与人类等级尚未经过比赛校准，挑战档也受资源限制。

每次搜索使用独立进程，避免跨房间共享棋局、参数与搜索表。UCI 发送初始 FEN 和完整棋谱，包括国际象棋的易位、吃过路兵、升变与重复历史。Fairy-Stockfish 的象棋 UCI 使用 1～10 路位编号，皮卡鱼使用 0～9，服务端显式转换。

根节点搜索范围限制为本项目规则判定的合法着法，引擎结果仍交正式规则引擎再次验证。房间跟踪回合、局号、行棋方、难度与取消代次；断线、结束、重开、移除和解散会取消旧搜索，迟到响应不应用。失败不改用其他引擎、其他难度或随机合法着法。

## 五子棋难度与搜索

| 难度 | 候选点上限 | 搜索深度上限 | 连续冲四深度上限 | 每手搜索预算 | 选择方式 |
|---|---:|---:|---:|---:|---|
| 入门 | 8 | 1 | — | 100 ms | 前四名加权随机，30% 概率忽略对手活三评估 |
| 简单 | 10 | 2 | — | 200 ms | 前两名随机 |
| 普通 | 12 | 4 | — | 500 ms | 取评分最高的着法 |
| 困难 | 15 | 6 | 8 | 1000 ms | 先找连续冲四，再按评分选择 |
| 挑战 | 20 | 逐层加深至时间上限 | 14 | 2000 ms | 先找连续冲四，再按评分选择 |

空盘走天元，其他局面只考察已有棋子两格内的空点。引擎在四个方向上识别从二连到五连的棋形，使用攻守评分排序，再以 alpha-beta 剪枝、迭代加深和 Zobrist 置换表搜索。简单及以上优先成五或封堵对手的一步胜着；普通及以上会识别并化解能形成活四的活三。对手已有两端都能成五的活四时，封堵其中一端可延缓对手获胜。困难和挑战用部分时间尝试证明连续冲四，剩余预算用于常规搜索。

五档搜索沿用本局规则。默认无禁手模式保留原有棋形评分和搜索顺序。黑方禁手模式下，常规搜索、攻防评分和连续冲四都使用服务端同一套黑棋判定。黑方只把恰好五连算作胜着，候选中过滤三三、四四和长连。执白时也只把黑方能合法形成的四和活三算作威胁。如果附近没有合法黑方落点，搜索会检查其余空点。

五子棋在独立 Node worker 线程计算，与原生引擎共用并发和排队上限。取消时终止旧 worker。时间预算从进入搜索开始计算，调度、线程启动及排队用时另计。完成后房间用正式五子棋引擎校验落点。

## 黑白棋难度与搜索

黑白棋沿用五档的候选数、深度与中前盘时间预算。入门深度 1，前四名加权随机；简单深度 2，前两名随机；普通深度 4；困难深度 6；挑战逐层加深至时间上限。对应候选上限为 8／10／12／15／20，预算为 100／200／500／1000／2000 毫秒。

搜索评估角位及相邻格、双方行动力，以及由角位固定的同色边子。普通至挑战档在中前盘优先占可下的角，余 12 格以内放开候选数和深度上限，选择最终净胜子数最大的着法。入门和简单档在残局仍按各自的候选数、深度和随机选点规则行棋。搜索计入自动停一手，仍受房间响应超时保护，可随对局取消。

两款自研引擎复用棋类 worker 调度。黑白棋在翻子间隔后启动电脑搜索，防止过早返回的应手打断前一手的 0.9 秒动画。服务器仍用正式规则引擎复核并提交落子。

三个引擎代码采用 GPLv3，原发行包许可及下载的源码保留在安装目录。Fairy-Stockfish 象棋网络由皮卡鱼开发者按 CC0 发布；皮卡鱼自用网络另有「未经许可不得商用」限制，见其发行包 `NNUE-License.md` 与[官方权重说明](https://github.com/official-pikafish/Networks)。分发二进制时需随附对应许可与精确源码来源；商业使用皮卡鱼权重需另行取得授权。

## 验证与边界

`tests/boardAi.test.ts` 使用明确的合成策略检查身份权限、空座位限制、难度校验、断线取消、迟到响应丢弃、无效走法、失败重试、终局与重开、清单损坏，以及 UCI 缺选项／退出／超时／取消。它不代替真实引擎验证。

`tests/gomokuAi.test.ts` 验证五档合法落点、固定种子、攻防棋形、三盘连续冲四、搜索预算与 worker 取消。房间测试覆盖实际挑战档完整对局、平板电脑执黑先下、五子棋人机悔棋不限次，以及悔棋被拒绝后电脑恢复思考。

`tests/renju.test.ts` 另用固定局面检查递归活三、同线四四、长连、成五优先级和双方 AI 的合法攻防，并验证规则切换、旁观快照、重开和战绩。

`tests/reversiAi.test.ts` 验证五档合法性、角位、残局穷举对照、房间完整流程及实际 worker 的落子和取消。

`npm run test:board-ai` 启动本机实际二进制和 NNUE，对全部十个「游戏×难度」组合各执行六手合法走子，定向检查双方升变与易位，再让真实房间对每个档位调度并应用电脑回复。报告写 `.board-ai/verification.json`。完整对局与正常取消的本机检查另保存在 `.board-ai/full-games.json`。

浏览器脚本与截图位于 `.tmp-visual/2026-10-30-board-ai/`，包含两个游戏的首页入口、五档选择、手机走子／刷新／教程／认输／重开／改回双人，以及平板后手、真实挑战引擎首步和多尺寸布局。真机触控与其他操作系统未实测；人类 Elo 与档位对战强弱校准尚未执行。
