# 旁观模式

八款游戏都可以旁观。打开朋友的入座邀请，在邀请页选「旁观」，或打开「工具 → 房间信息」提供的旁观链接。房间信息显示当前旁观人数，每房最多 8 位在线旁观者。

斗地主和掼蛋必须横屏。手机沿用单独手机牌桌，显示座位、剩余张数、公开出牌与底牌状态；平板使用公共牌桌。棋类必须竖屏，使用先手方在下的中立棋盘，可看到公开行棋和电脑思考状态。设备方向不符时沿用旋转提示。旁观页可返回大厅、入座或发固定快捷语。房主可在「工具 → 房间信息」关掉旁观快捷语。

## 隐私与凭证

- 旁观者的游戏部分直接取自 `engine.view(null)`。房间附加的手牌和座位申请队列为空，`selfSeat` 为 `null`，`isHost` 为 `false`。提示只发送给请求提示的玩家。旁观者能看到座位、剩余张数、已打出的牌和公开结算。
- 斗地主底牌等地主确定后才公开。掼蛋的贡牌和还牌按引擎规则公开，候选牌和未公开提交留在该座位私有视图中。军棋的暗子不带军衔，司令阵亡亮出的军旗可以看到，棋局结束后公开剩余棋子。
- 旁观凭证与玩家和房主凭证分开。浏览器把它保存在本标签的 `sessionStorage`，使用 `ddz:spectator:<房间号>` 保存该房间的旁观身份。刷新会以原身份恢复。在线人数不含掉线观众；当保留的身份已满，新观众会复用断开的旁观名额，旧凭证需重新旁观。
- 观众不能发出对局、准备、悔棋、人机、托管或房主命令。观众断线不会暂停对局，也不会延长无玩家房间的过期时间。

## 从旁观入座

准备阶段，房间已放置的空座可以直接入座。已有玩家的座位使用原有「申请替换」流程，由房主同意或拒绝。批准前该连接仍收公开快照。批准或直接入座后，同一连接换发玩家凭证，旁观人数减一，开始收到该座位的私密视图。平板同屏棋类由本地双方操作，旁观者无需占座。

## 验证

- 运行 `npx tsx --test tests/spectators.test.ts tests/controllerPersistence.test.ts`。分别验证八款游戏的旁观快照与 `engine.view(null)` 一致，递归检查私有手牌、底牌、军衔和掼蛋交换内容。测试也覆盖命令拒绝、人数上限、凭证、过期和入座前后的快照。
- 运行 `npm test` 和 `npm run build`。启动服务后运行 `npm run test:junqi:ws`，通过真实 WebSocket 分别验证双人和四国军棋的旁观、暗子隔离、重连与终局公开。
- 浏览器可以用独立页面打开同一房间。让三位玩家完成一局手机斗地主，用第四页旁观并刷新。另开双人军棋房，检查布阵、行棋与终局；在空座入座和房主审批接替前后核对旁观人数与可见内容。
