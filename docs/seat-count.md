# 2–8 人房间座位

房间共用的座位上限是 8，定义在 `shared/tableSeats.ts` 的 `MAX_SEATS`。旁观名额独立计算，每房最多 8 位在线旁观者。现有游戏继续用各自的座位数、坐标和轮转顺序。军棋继续通过「双人暗棋／四国暗棋」切换。

## 为阶段 10 注册游戏

1. 按[游戏注册表](game-catalog.md)登记真实游戏。在 `shared/gameCatalog.ts` 为它声明默认 `seatCount`、`minSeats` 和 `maxSeats`。三者均为 2 到 8 的整数，默认值在范围内。固定人数游戏把这三个值设为同一个数。
2. 可变人数游戏在规则引擎实现 `setSeatCount(count: number): GameResult`，并让 `RoomGame.seatCount` 返回当前值。成功时一次性调整人数和按座位索引的引擎状态。拒绝时保留原局面。实现 `restart()` 时保留人数，发牌时用实际参与人数调用 `context.onDeal`。
3. 房主在准备阶段发送 `seatCount` 和 `{ count }`。房间负责范围、权限和占座校验，按座位编号保留玩家和手牌权限。缩减尾部前须腾空相关座位，已移除座位上的待处理申请会通知申请方。成功改人数后，真人重新准备，机器人和托管座位保持准备，旁观连接继续使用。
4. 可变房间的快照通过 `seatCountSettings` 提供当前人数和范围。平板只回传已放置的座位，准备条件应读取房间设置或目录默认值，避免把已放座位的数量当作目标人数。

房间层的凭证、准备、托管标记和倒计时支持扩容。每款新牌类游戏仍需实现自己的牌型、公开桌面和自动出牌策略。现有斗地主和掼蛋的模型输入继续使用各自规则的人数。

## 手机与平板坐标

新游戏使用 `phoneSeats(n)` 在归一化牌桌边缘等距放置座位。座位 0 在底边正中，编号递增朝右侧前进，接着经过上侧和左侧。角度与牌桌朝向一致，底、右、上、左分别为 0°、−90°、180°、90°，其他位置朝桌心旋转。现有游戏的手写坐标优先，保留原有顺序。

5–8 人的平板桌会缩小座位框，并显示按顺序可点击的推荐位置。也可继续轻点桌边手动放置。采用推荐位置需要逐座确认。缩减人数时保留剩余座位的手动坐标，扩增时继续放置新增座位。已有人入座时，已放座位沿用原有的固定规则。

## 测试接入

`tests/seatCount.test.ts` 通过房间构造函数的第三个参数传入仅用于测试的 `RoomEngineSetup`。这个内存对象包含测试目录元数据和引擎工厂。WebSocket 创建入口只接收经 `isGameKind` 校验的正式游戏名，测试牌桌不在游戏目录、前端入口或可创建的游戏列表中。

`tests/phoneSeatsSnapshot.test.ts` 锁住现有手机坐标，包括军棋的两种模式。`tests/tabletSeatLayout.test.ts` 检查 5–8 人的推荐位置在 1024×768 与 768×1024 下的旋转足迹。
