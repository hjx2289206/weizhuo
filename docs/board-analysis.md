# 中国象棋与国际象棋复盘分析

终局后，入座玩家或同屏主机可在棋谱旁点「分析本局」。分析期间可取消，失败时保留已完成局面并显示中断原因，可以重新分析。旁观者可以查看进度、已完成的结果和推荐走法。

点曲线上的圆点或棋谱中的着法，棋盘会切到该步之后的局面。有合法推荐时，棋盘用虚线箭头标出当前局面的推荐走法。「回到终局」恢复最后的盘面。平板同屏的复盘板面朝向主机一侧，手机棋盘沿用玩家自己的朝向。引擎参考，非绝对结论。

## 评分与着法

每局有 N 步棋和 N+1 个局面。双方评分都换成红方或白方视角画图，显示范围是 ±1000。正分表示红方或白方优势。将杀评分按将杀步数换成 ±(10000 − 步数 × 10)，已将死的一方记为 −10000。

每步损失使用走子方视角，先把前后评分分别限制到 ±1500，再计算走子前减去走子后的差值，最小为 0。

| 损失 | 标记 |
|---:|---|
| 300 及以上 | 大失误 |
| 150 至 299 | 失误 |
| 70 至 149 | 欠佳 |

## 引擎与任务

国际象棋使用 Stockfish，中国象棋优先使用皮卡鱼，皮卡鱼不可用时使用 Fairy-Stockfish。引擎需要通过服务端安装校验，缺失时按钮会给出原因。复盘使用满强度，一个任务启动一个 UCI 进程，依次分析各局面，每个局面限制为 50,000 节点或 150 ms。以最终推荐前的最后一条评分为准，同一深度优先用精确分，推荐走法需通过本项目的规则校验。

将死及中国象棋困毙直接记负的将杀分。国际象棋逼和或子力不足直接记 0。认输、协议和棋、超时和重复局面等结束方式仍然分析最后的棋盘。

服务同时只接收一个复盘任务，忙时请稍后重试。运行进度最多每 500 ms 更新一次，完成或失败立即通知。再来一局或房间销毁会取消任务并清空结果。结果随房间保存在内存里，本地战绩只保存原有公开结算。

## 验证

`npx tsx --test tests/boardAnalysis.test.ts` 使用模拟策略和假的 UCI 子进程验证协议、评分、进度、权限、终局、取消和资源回收。`npm run test:board-ai` 分别用真实引擎分析两盘固定的 20 步棋谱，校验大失误并将耗时写入 `.board-ai/verification.json`。
