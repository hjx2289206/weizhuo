# 围桌 · 和朋友开一局

支持局域网联机、平板同屏与本地 AI 对弈的棋牌合集，基于 Vue 3、TypeScript 和 WebSocket。

本仓库收录**八款游戏**：**中国象棋**、**国际象棋**、**围棋**、**五子棋**、**黑白棋**、**军棋（双人／四国暗棋）**、**三人斗地主**与**四人掼蛋**（两副牌 108 张、两队搭档）。斗地主与掼蛋支持「平板开一桌」和「手机开一桌」；中国象棋、国际象棋、围棋、五子棋、黑白棋均支持平板双人同屏和手机联机；军棋提供真人「联机对弈」，每位玩家使用自己的私人屏幕。服务端权威判定，无账号、无数据库，房间仅存在内存中。

斗地主与掼蛋带**本机机器人和托管**：斗地主使用本机 DouZero，掼蛋使用 DanLM 仓库的两个官方掼蛋网络（安装与机制见 §1 与 §2）。中国象棋、国际象棋、五子棋与黑白棋另支持五档本地 CPU 人机对弈，军棋仅支持真人联机。

- 服务端：`server/**`（Node http + ws，生产环境托管 `dist/`）；各游戏的引擎在 `server/games/**`
- 共享层：`shared/protocol.ts`（协议）、`shared/gameCatalog.ts`（实际收录的游戏与桌位事实）、`shared/guandan.ts`（掼蛋牌型、比牌与进贡判定）、`shared/inAppBrowser.ts`（内嵌浏览器硬阻断）
- 前端：`src/screens/**` 为大厅与两种设备模式；`src/style.css`、`src/collection.css` 为样式；`src/components/PlayingCard.vue` 为原创 SVG 牌面；`src/handheldLayout.ts` 为握牌几何
- 测试：`tests/**` 覆盖各游戏的牌型、棋规与流程、房间身份与权限、重连与接替、公开记牌统计、浏览器识别及幂等边界

## 旁观模式

八款游戏都支持旁观，每房最多 8 位在线旁观者。在入座邀请页点「旁观」，或从「工具 → 房间信息」分享旁观链接。牌类横屏，手机使用单独手机布局，平板使用公共牌桌；棋类竖屏。旁观页只显示公开信息，刷新后仍可旁观。空座可直接入座，接替已有玩家的座位仍需房主同意。房主可关闭旁观快捷语。详见 [旁观模式与隐私验证](docs/spectators.md)。

## 动画机制教程

进入任一游戏后，右上角「教程」会打开按机制分段的动画：先展示局面，再自动演示动作，最后停在结果。无需出牌或行棋。可以暂停、继续、重播，用上一段、下一段或目录选段；观看进度独立保存。纸牌教程使用横屏，竖屏时暂停并提示旋转手机；军棋可以放大关键路线和交战位置，不教学布阵；中国象棋与国际象棋教程使用竖屏；中国象棋还会放大关键走法与挡子。

所有片段由现有正式规则引擎和固定剧本生成，牌型、交换、结算、升级和胜负仍真实计算。失败尝试显示原因并保持局面不变。教程不调用机器人模型、不占用正式桌位、不写入聚会战绩；原房间保持连接，打开教程不会暂停原对局。

教程使用独立 `/ws/tutorial` 通道，协议、动画和验证方式见 [教学实现说明](docs/animated-tutorial.md)。

## 中国象棋与横屏大厅

首页只展示“棋类／牌类”两个大分类入口，进入分类后才显示对应游戏，点“返回分类”可切换。分类内每页最多三款游戏，后续游戏用分页查看。昵称和牌类练习难度在分类内设置；首页保留“加入朋友”和“继续对局”。首页横屏，棋盘竖屏，均使用固定一屏布局，禁用页面滚动，按手机和平板尺寸单独适配。方向不对时提示旋转；浏览器允许时使用原生方向锁定。加入房间用弹层，规则、棋谱和战绩用分页查看。

大厅的游戏分类与展示顺序由共享游戏目录提供，规则页签、开房、教程和本地战绩也使用该目录。登记新游戏时可参照 [游戏注册表](docs/game-catalog.md)。

象棋支持两人共用一块平板直接开局，不需要手机或准备；红黑棋字各朝向自己的玩家。也支持双手机邀请和准备，红方先行，合法落点提示、将军应将、将死与困毙、认输、和棋、断线恢复、棋谱及战绩。棋盘和圆形棋子使用 SVG，静止和移动共用同一组件。提供 40 段象棋动画教程和文字规则，手机棋字统一朝下，平板同屏棋字相向。循环局面采用明确的休闲裁定，详见 [中国象棋说明](docs/xiangqi.md)。

## 国际象棋

从首页进入“棋类”后可选国际象棋，参照中国象棋提供「平板双人同屏」「联机对弈」和「人机对弈」。平板免入座、免准备，白方在下、黑方在上，两方棋子各朝自己；手机联机各自阵地在下，双方准备后房主开局。棋盘与六种立体轮廓棋子均由原创 SVG 绘制。

支持全部基本走法、长短王车易位、吃过路兵、四种升变选择、将军与将死、逼和、子力不足、认输和协议和棋。提供 39 段动画教程、分页文字规则、棋谱和战绩。三次重复及 50 回合规则采用自动和棋的休闲约定。实现与验证见 [国际象棋说明](docs/chess.md)。

## 围棋与五子棋

棋类第一页可进入围棋与五子棋。两者均提供 SVG 棋盘、手机联机、平板双人同屏、棋谱和战绩。先预选交叉点，再确认落子。

围棋支持 9、13、19 路，数子法、黑贴 7.5 点、提子、禁入点和盘面同形再现限制。双方连续停一手后确认死子，双方确认才结算；有争议可继续下棋。**13 段基础教程与 9 段进阶教程独立选择、分别保存进度**；进阶附经网上检索的中文课程、19 路进阶及高级官子课程供选看，外站登录和费用以原站为准。详见 [围棋规则与课程来源](docs/go.md)。

五子棋采用 15 路棋盘，默认无禁手，也可在准备页由房主选择「黑方禁手」。启用后，黑方须恰好五连，三三、四四和长连会被拒绝；白方五连或长连均获胜。棋谱和战绩附本局规则，另有 13 段动画教程。两种规则都支持五档人机。手机默认玩家执黑，平板可选执黑或执白。详见 [五子棋说明](docs/gomoku.md)。

## 黑白棋

棋类分类第二页可进入黑白棋。支持 8×8 原创 SVG 棋盘、平板同屏、手机联机、五档人机、棋谱、战绩和八段动画教程。黑方先行。选有小圆点的格子并确认，夹住的对手棋子会翻面。无合法落点的一方自动停一手，终局按子数判胜。详见 [黑白棋说明](docs/reversi.md)。

## 棋类悔棋

中国象棋、国际象棋、围棋、五子棋和黑白棋支持悔棋。手机联机由对方同意后退到请求者上一手之前，平板同屏由两人确认后撤销上一手。真人对局每方每局可以成功悔棋 3 次。人机对弈等电脑走完后可直接退回到自己上一手之前，次数不限。详见 [棋类悔棋](docs/board-undo.md)。

## 棋类行棋反馈

中国象棋、国际象棋、军棋的正式对局都会播放约 0.9 秒的走子过程：先移动，再处理吃子／交战；起点、终点及方向路线保留到下一步。象棋遵循马步、象步和炮的动作；国际象棋易位同时移动王与车，吃过路兵从实际位置移除被吃兵，升变在落地后显示新棋子。手机视角、平板相向棋子和人机模式沿用各自的朝向。

围棋与五子棋显示确认后的落子、短暂涟漪和黑白对比的末手标记，不把落子伪装成棋子滑行；围棋先落子，再淡出被提棋子，并显示提子坐标。“停一手”明确显示且清除旧落点标记。所有棋类共享 `src/useBoardPlayback.ts` 的连续快照播放与取消机制；重连不补播历史，减少动态效果时保留静态提示，最后一步播完才展示结算。

2026-11-06 验证：完整测试 357 项通过；浏览器实际双页面验证了四款棋类的对手行棋／落子，另验证平板相向棋字、电脑回棋、围棋 9／13／19 路、五子棋获胜落子与结算顺序，以及 320×568 小屏操作区。浏览器尺寸模拟不等同于真机触控验收。

## 中国象棋与国际象棋 AI

进入棋类分类后，游戏卡片的「人机对弈」可直接开房并选择 **入门、简单、普通、困难、挑战** 五档；也可在准备页设置。手机默认玩家先手，平板可选择先手或后手；与电脑对弈时自己的阵地在下、棋子统一正向，双人同屏保留相向棋子。

国际象棋使用 Stockfish；中国象棋前四档使用 Fairy-Stockfish，中国象棋挑战档使用皮卡鱼。全部通过本机 CPU 的原生 UCI 引擎运行，难度是引擎参数与计算预算的相对档位，没有标注未经校准的人类 Elo。

```bash
npm run setup:board-ai   # 官方固定版本引擎、NNUE 与 SHA256 清单，保存在 .board-ai/
npm run test:board-ai    # 实际 CPU 搜索、全部十个难度组合及房间自动行棋
```

安装完成后重启服务。缺失、损坏或启动失败的引擎对应难度会保持不可用，正式对局不使用随机或自写走法代替。棋规仍由本项目服务端验证。人机对弈提供认输与棋规自动和棋，协议和棋仅供双人对弈。说明、版本、许可与验证边界见 [棋类 AI](docs/board-ai.md)。

## 军棋（双人／四国暗棋）

棋类分类共用一个军棋入口，在房间内由房主选择「双人暗棋」或「四国暗棋」。仅支持真人联机，各人使用私人屏幕，不提供公共平板棋盘。邀请两位或四位玩家入座并准备后开始布阵；切回双人前需让第三、第四座离座。

军棋始终竖屏，己方阵地朝下，棋盘与操作区上下排列；进入军棋后解除大厅横屏锁定。军棋页面可纵向滑动：屏幕较小时向上滑动即可操作准备、开始布阵、邀请和规则，不受大厅禁止页面滚动的限制；保留底部安全区，避免按钮被系统手势区遮挡。四国采用 SVG 十字棋盘，支持全盘、放大后滚动，以及「我的阵地」视图；布阵时默认聚焦自己的阵地。

- **准备与布阵**：所有座位入座并准备后，由房主开始布阵。每方 25 枚，军旗在大本营、地雷在后两排、炸弹不在第一排，行营开局空置。点击己方棋子，再点击合法位置交换，或随机布阵；全员确认后红方先行。
- **行棋与交战**：公路一步，铁路直行不限格；四国外围印制弯道可沿轨通过，普通棋子不可在铁路路口换向，工兵可以。均不可越子或攻击队友。行营内棋子受保护，大本营内棋子及地雷、军旗不可移动。军阶依次比较，同级同归于尽；工兵排雷，其他军衔撞雷败；炸弹与任何敌子同归于尽。司令阵亡亮军旗。
- **行棋提示与动画**：双人及四国实局都会沿公路／铁路路线播放约 0.9 秒的走子和交战动画，保留带行棋方颜色的路线、“起／落”标记，以及上一手的坐标和结果。四国开始走子时切回全盘，避免“我的阵地”遮住对方行棋。动画使用行棋前该玩家能看到的棋子，暗子始终显示“暗”；系统开启减少动态效果时仅显示落定局面和路线。重连不补播旧步，仍保留上一手提示。
- **四国组队**：红绿同队、蓝紫同队，对坐同盟，按红、蓝、绿、紫顺序行动。队友身份同样隐藏，属于四国四暗。夺旗、无棋可走或认输，仅该军出局并清除其余棋子，搭档继续；回合跳过出局者，敌队全军出局获胜。连续 70 步无交战和棋。
- **隐私与恢复**：服务端对每个接收者单独投影，只发送该座位自己的暗子身份；棋子 ID 随机不透明，公开棋谱不含隐藏军衔。结束后公开剩余棋子。重连沿用同一身份与棋局；未出局的玩家断线时暂停。房间仍是内存态，服务重启清空。
- **战绩**：结束后保存本浏览器的公开结果与行棋记录，四国按队伍结算；支持回顾和 PNG 导出，不保存身份凭证或运行中的私有棋盘。
- **规则参考**：[2025 年安徽省大学生计算机博弈大赛军棋项目](https://cxcyxy.chnu.edu.cn/xkjs/content_134586)的基本棋规、[中央民族大学军棋说明](https://jsjby.muc.edu.cn/info/1017/1022.htm)的无棋可走及和棋约定，以及 [SiguoZero](https://github.com/wyx66624/siguozero) 的四国棋盘拓扑参考。本版本固定四暗、出局清子、红方先行及 70 步和棋；未实现翻棋、双明或队友互看。

验证命令：`npx tsx --test tests/junqi.test.ts tests/junqiFour.test.ts tests/boardPlayback.test.ts`。服务启动后执行 `npm run test:junqi:ws`，通过真实 WebSocket 分别完成双人和四人对局，验证机器人／托管命令被拒绝、公共平板模式拒绝、暗子隔离、重连、完整对局、下一局与解散。测试使用临时房间。

## 1. 启动

```bash
npm install          # 首次安装依赖

npm run dev          # 开发：单进程 HTTP 服务，0.0.0.0:5180，内置 Vite 中间件（热更新）
npm run build        # 生产构建：vue-tsc --noEmit && vite build -> dist/
npm start            # 生产运行：tsx server/index.ts --production（托管 dist/，内存态）
npm test             # tsx --test tests/*.test.ts
```

- 端口默认 `5180`，可用环境变量覆盖：`PORT=8080 npm run dev`。
- `dev` 只有一个进程：HTTP + WebSocket（`/ws`）由同一个服务提供；生产模式同样如此，只是不再挂 Vite 中间件。
- 邀请用的局域网地址由 `GET /api/network` 返回：`{"urls":["http://192.168.x.x:5180", ...]}`。

### 斗地主机器人（DouZero）运行时（可选 · 一次性安装）

```bash
bash scripts/douzero-setup.sh   # 可重复执行：建隔离 venv、按固定提交拉官方源码、校验权重 sha256
npm start                       # 或 npm run dev：启动时先 initializeDouZero()，再 listen
```

两款游戏现统一使用 **ONNX Runtime / CPUExecutionProvider**：斗地主三个角色、掼蛋强档 Transformer 和易档 MLP，共五个 ONNX 文件。保留原始训练权重和选牌逻辑，运行时不导入 Torch、MPS、CoreML 或 CUDA；强档仍按网络评分选牌，易档行为不变。

- **推理环境**：`.ai/venv`，仅安装 `requirements-ai.txt`（NumPy、ONNX Runtime）。模型在 `.ai/models`，加载时校验 `manifest.json` 中的 SHA256；缺失或损坏时公开报错，停止 AI 自动出牌。`AI_CPU_THREADS` 默认 2，限制为 1–4；`AI_PYTHON`、`AI_MODEL_DIR` 可覆盖运行时与模型目录。
- **原始权重与来源保留**：`.douzero/weights/douzero_WP/*.ckpt`、`.guandan/DanLM/ckpts/` 只用于导出及对比。两个旧 venv 只用于上游准备或离线验证，不用于服务推理。源码和模型来源哈希记录在 `.ai/models/manifest.json`。
- **新安装**：分别执行 `bash scripts/douzero-setup.sh`、`bash scripts/guandan-setup.sh`。脚本准备固定版本上游源码及权重后，调用 `scripts/ai-export.sh` 导出，再安装通用推理环境。导出环境 `.ai/export-venv` 使用 `requirements-ai-export.txt`，与推理环境隔离。可通过 `PIP_INDEX_URL` 选择 pip 源。
- **已有模型包**：复制 `.ai/models` 后，执行 `bash scripts/ai-setup.sh` 即可安装推理依赖。不要跨系统复制 venv。掼蛋当前仍需要 macOS ARM64 / Python 3.12 的上游规则和编码扩展；**模型推理已通用，整个掼蛋服务尚不能直接迁到 Linux**。斗地主的规则与编码是 Python 源码。Linux 实机验证尚未进行。
- **验证**：`npm run test:ai` 检查干净 CPU 推理环境、五个模型动态输入，以及真实 worker → Node 校验 → 本项目规则引擎连续两副对局；`scripts/ai-parity.py` 在离线导出环境对比原模型整局评分，`scripts/douzero-audit.py` 校验官方观测与公开状态重建。详见 [CPU 模型迁移说明](docs/ai-cpu-migration.md)。
- `.ai/`、`.douzero/`、`.guandan/` 均为本地依赖目录，已忽略。原始权重、导出包和验证报告需要随部署单独保存。人工对局不依赖这些模型，AI 不可用时也可以启动服务。

## 2. 局域网使用

电脑运行服务，所有设备连同一个 Wi-Fi。浏览器打开 `http://<电脑局域网IP>:5180`；地址可在启动日志或 `GET /api/network` 查看。本机可用 `http://127.0.0.1:5180`。

### 平板开一桌

1. 平板在大厅选好游戏后点「平板开一桌」。
2. 斗地主在牌桌边缘依次放置三个座位，连点也会按顺序记录。掼蛋自动放好下、右、上、左四个固定座位，不提供自定义位置；上下同队、左右同队，按下 → 右 → 上 → 左轮转。
3. 点座位显示专属二维码，链接为 `?room=CODE&seat=N`。手机扫码后填昵称、入座、点「准备」。
4. 全部座位都有人（或房主放好的机器人）并且都准备好后，平板房主点「开始游戏」。平板始终不接收任何人的私有手牌。
5. 斗地主还无人入座时可重放或重置座位；有人入座后，已放位置与编号固定，只能追加剩余空座。掼蛋的位置和编号始终固定。

房间号为不区分大小写的四位字符（A–Z 去掉 I、O，加 2–9）。斗地主座位号为 `0/1/2`，界面显示 `1/2/3 号座`，出牌顺序 `0 → 1 → 2`；掼蛋座位号为 `0..3`，界面显示 `1..4 号座`，出牌顺序 `0 → 1 → 2 → 3`，座位 `0` 与 `2`、`1` 与 `3` 各为一队。

### 手机开一桌（无需平板）

1. 一台手机在大厅填昵称、选好游戏，点「手机开一桌」；创建者同时是玩家与房主。
2. 在房间中用「邀请」把剩余座位的链接发给其他玩家，或让他们在大厅输入房间号与座位。
3. 全部玩家准备后，由房主开始。每台手机显示自己的手牌、当前墩出牌与公开信息；斗地主另有公开底牌，掼蛋有级牌标记、名次与队伍进度。
4. 连续不出后，手机上的当前墩清空；记牌器仍使用整局公开历史。结算后只有当前房主可点「再来一局」（斗地主），掼蛋则是「下一副」，整场分胜负后为「再来一场」。
5. 手机房主断开后，房主权限转给在线玩家；全部离线后，首个持原凭证恢复的玩家接管。原房主稍后回来不会抢回权限。

### 手机上的对局信息（两款游戏）

- 手机不模拟桌面：没有牌桌底色、边框、圆角或阴影，界面就是纸面。
- 每位对手只占一行紧凑信息：圆形头像内是名字首字，旁边是「剩 N 张」。头像带有完整真名的 `title` / `aria-label`；斗地主地主的头像带小王冠（`♛`），掼蛋对家的头像用另一底色圈出。不出现「我方／对方」之类的中央标签，也不重复显示自己的剩牌数。
- 机器人头像角上带一个机器人小标记（现在写明档位：`机器人·强` / `机器人·易`，`title` / 以及 `aria-label` 说明「由服务器自动出牌，可申请替换该座位」）；被托管的真人用一行小字标「托管」，离线时是「托管 · 离线」。**机器人和托管都不是「掉线」**，只有没托管的真人才显示「离线」。
- 开局前那一行显示「已准备／未准备」，不谎报「剩 0 张」；未入座的座位显示「待加入」，也只算待加入，不算掉线。
- 自己的身份只在页头保留一个小头像（首字 + 完整真名的无障碍标签）；掼蛋的「打 N」级牌标记也留在页头，本副名次与队伍进度在结算面板。
- **平板不做这套精简**：公共桌面保持原有的四方位坐席、朝向与显眼的大号剩牌数，平板只是展示，不是私人界面。

### 机器人与托管（两款游戏）

- **加／移除机器人（两款游戏都有强/易两档）**：准备阶段，房主可以给「已经放好、但还没人坐」的座位放一个机器人（默认名字 `机器人N`，自动准备、没有 socket），也可以随时移除；这些按钮只在准备阶段出现，服务端也会拒绝准备阶段以外的增删。**掼蛋**两档对应 DanLM 官方注册表里的两个网络：强 = Dansformer transformer（`danlm_v1`），易 = 轻量 ONNX 网络（`danzero_v1t`）。**斗地主**只有一个官方 DouZero 模型，易档不换模型：推理 worker 返回全部合法走法按网络估值排序的榜，强档总是取第一名（官方 argmax），易档在最优 5 名里按价值做 softmax 加权抽取（会犯一些合理错误，绝非随机乱出）；候选不符合本服规则时自动回退到榜首走法。叫分对所有机器人/托管座位都用 §2 的确定性本地规则，与难度档无关。机器人座位头上公开一个 `botTier`（强/易），界面会如实显示。
- **自己托管**：已入座的斗地主人可以自己点「托管」把本座位交给本机 DouZero 自动出牌，**准备阶段也能开**（开启时该座位同时算已准备，准备按钮变成「托管已准备」并禁用）；托管期间手动叫分、出牌、不出都会被拒绝（提示「托管中，请先取消托管」）；「取消托管」永远可用——即使在托管之后运行时挂掉也能取消，取消后就恢复手动操作。
- **断线、暂停与回收**：机器人不依赖手机连接；真人主动开启托管后，即使关闭浏览器或断线，也照常自动出牌。未开启托管的真人掉线，仍然让全桌暂停等重连（提示「有玩家掉线，等待重连」）。全程托管、还在推进的对局不会被 30 分钟空置规则回收；无人连接的准备或结束房间照常回收。
- **重连与接替**：刷新、重连会保留托管状态，随时可以取消。真人想坐机器人（或其他）座位仍走原有的「申请替换 + 房主同意」流程；批准后该座位变回手动操作（`isBot`／`autoPlay` 都清掉），并且**在把新 session 交给新设备之前，先作废那次还没提交的机器人决策**，旧推理不会顶替新玩家。机器人也不会成为手机房的房主。
- **失败如实报错，不偷偷换牌**：运行时不可用、权重缺失、worker 崩溃或推理超时都会公开报错（例如「机器人推理失败，已停止自动出牌」「机器人推理超时，已停止自动出牌」）；牌局状态保留、托管停住等人工取消，**不会**悄悄改成出最小牌或随机牌，也不会把「本来就没装 DouZero」说成能用。
- 掼蛋每次自动行动前保留 250 毫秒间隔，再运行原有模型；发牌期间仍等待所有牌到位和翻面完成。斗地主保留原来的 600 毫秒节奏。
- **出牌是 DouZero，叫分不是**：接入的这套 DouZero 预训练出牌模型不含叫分网络，叫分由服务端一个具名、确定性的本地规则完成（第一个叫分位置必叫 1 分，之后按自己手里的强度牌数决定要不要加叫）；出牌来自加载的网络，牌型合法性仍由本仓库自己的规则再校验一次。
- **控件位置与透明操作条**：托管入口位于页头或准备区，添加／移除机器人位于房主的座位控制区。经典／记牌器及纯手机布局的出牌、不出等操作行已移到私人手牌上方，背景透明，不覆盖点数与花色；关闭记牌器的大扇形握牌仍保留底部操作。手牌几何、平滑切换和选牌保留逻辑不变。
- **没有实力结论**：仓库只验证了「确实加载官方三个角色网络、在本机 CPU 上做出真实且合法的出牌」，**没有做过胜率／棋力测试**，也没有真机验证。

### 关闭浏览器、重连和换人

- **同一浏览器**重新扫码、打开原座位链接、手动加入原房间与座位，或在大厅点「继续游戏」，会优先使用本机保存的凭证恢复原身份、手牌、回合与积分，不重复入座。
- 「返回大厅」是暂离，不删除本机的继续游戏凭证。房间仍需满足下方的内存与离线保留限制。
- **换手机、换浏览器或换玩家**时，扫码链接会先读取公开的游戏与座位信息；已占座位可直接选择「申请替换」，对局中也能申请。新设备在等待区保留昵称，房主可同意或拒绝；旧设备在线时会明确警告它将被挤下线。批准后只更换设备与姓名，不重发牌、不重置积分或回合。
- 新设备在批准前没有身份或私有手牌。批准会撤销旧凭证；旧设备不能再操作或读取该座位的手牌。
- 同一身份在另一窗口恢复后，旧窗口会回到大厅并停止自动重连，避免两个窗口反复互踢；可主动点「继续游戏」再次接手。
- 玩家可用「改名」修改自己的昵称。邀请链接只含房间与座位，**不包含 token，也不自动迁移跨浏览器身份**。

### 纯牌桌模式（平板）

- 头部只有一个「全屏牌桌」入口：隐藏页头、底栏与常驻按钮，牌桌铺满视口；玩家姓名、身份与显眼的剩牌数保留在各自座位处，掉线不会把牌数变成零。
- 进入时按浏览器能力顺带申请一次整页原生全屏，座位二维码弹窗也在其中。被拒绝仍可使用纯牌桌，并如实提示；没有单独的浏览器全屏按钮。
- 长按空白桌面约 0.55 秒打开控制面板，移动手指会取消；桌面浏览器也可双击空白处。面板内可邀请、处理接替申请、开始、重开或退出牌桌。点外侧或 Esc 先关闭面板，再按 Esc 退出；系统退出原生全屏也回到控制视图，均不改变牌局。
- 斗地主的底牌三张保持大牌、居中并朝向地主；掼蛋没有底牌，四方位座位与桌面上的公开出牌照常保留。每手出牌落在中心偏出牌人一侧，按其方向旋转，加上服务端一次生成的轻微随机位置与角度；不同手牌可以互相覆盖，也可以盖住底牌。
- 平板保留本局所有有效出牌，结算时仍可查看；房主点「再来一局／下一副」进入下一局准备时清空。刷新与重连不会重新随机落点。

### 手机手牌与记牌器

- 平板模式的手机默认是**大扇形握牌**：斗地主 20 张约 82°、17 张约 70°，常见横屏宽度下牌宽约 122–154px；掼蛋 27 张使用同一套几何，扇面到上限 82°，牌宽随可用空间适配。每张露出点数与花色，只有握住的下方牌尾可被裁掉。
- 点按选中/取消，横向划扫连续选牌，先选牌再上滑出牌，也可点「出牌」。手势只从手指下**实际画出牌面的那张**开始，浏览器的触摸重定向不会误选邻牌，空白处不会选牌或出牌；划扫开始后仍会连续补齐经过的牌。临时抬起和预览在松手后收起，选中保留描边。
- 只有一个「记牌器」按钮，不再提供独立的「经典／握牌」按钮。平板模式中，关掉记牌器用大扇形；打开则平滑切换到紧凑经典手牌，并在上方显示统计。切换保留选牌与身份；刷新会重新同步手牌，**不保留当前选牌**。
- 纯手机模式保持紧凑手牌，记牌器以可拖动、可关闭的悬浮窗打开，不切换手牌布局。
- 记牌器在进入出牌阶段后可用（斗地主需先确定地主）。按点数显示**外部尚未出的张数 = 牌堆总数 − 已公开打出的牌 − 我的手牌**。斗地主一副 54 张，每个点数 4 张、大小王各 1 张；掼蛋两副共 108 张，每个点数 8 张、大小王各 2 张，行序按掼蛋牌力排列，级牌一行单独标出。自己出牌时外部数量不变，对手出牌时相应减少；不会读取或推断对手的私有手牌。
- 点「准备」的真实手势会申请原生全屏，再尝试锁定横屏。竖屏只显示「点击进入横屏牌局」这一个入口，叫分、进贡、还贡与出牌都必须处于横屏视口（提示语对 20 张和 27 张手牌通用）；不支持或拒绝 API 时会如实提示，只有实际横屏后才能选择「继续浏览器横屏」。转回竖屏会重新拦住，不循环自动申请。网页不能绕过系统权限，实际能力取决于设备、浏览器与版本。

### 微信 / QQ 内置浏览器：必须换外部浏览器

- 微信 `MicroMessenger`、QQ 聊天 `QQ/<版本>` 与 `QQHD/<版本>` 只显示阻断页：**没有关闭、继续或 Esc 绕过入口**，不会加载游戏控制器或打开游戏 WebSocket；服务端也在升级 `/ws` 前返回 403。
- QQ 浏览器、单独的 `MQQBrowser`／`TBS` 内核标记不按 QQ 聊天宿主拦截，普通 Safari／Chrome 可进入。
- 使用右上角菜单的「在浏览器打开」，或点「复制链接」后粘贴到外部浏览器。没有自动唤起外部应用或自动跳转；只有主动复制才写剪贴板，失败会提示选中链接手动复制，不假报成功。
- 建议先换浏览器再入座；已经入座后换浏览器或手机，需由房主确认接替。识别是 UA 启发式，不是防伪认证，也不保证外部浏览器一定支持全屏或方向锁定。

## 3. 斗地主规则（精确说明）

### 牌

54 张：`3..15`（15 即 2）各 4 种花色（♠♥♣♦），外加小王 `rank 16`、大王 `rank 17`。每家 17 张，底牌 3 张。

### 合法牌型

| 牌型 | kind | 说明 |
|---|---|---|
| 单张 | `single` | 1 张 |
| 对子 | `pair` | 2 张同点 |
| 三张 | `triple` | 3 张同点 |
| 三带一 | `triple_single` | 3 张同点 + 1 张任意单牌 |
| 三带二 | `triple_pair` | 3 张同点 + 1 个对子 |
| 顺子 | `straight` | ≥5 张连续单牌，最大牌 ≤ A（不使用 2 和王） |
| 连对 | `pairs_run` | ≥3 个连续对子，最大牌 ≤ A |
| 飞机（不带翅） | `triples_run` | ≥2 个连续三张，最大牌 ≤ A |
| 飞机带单翅 | `airplane_single` | n 个连续三张 + n 张单翅 |
| 飞机带对翅 | `airplane_pair` | n 个连续三张 + n 个对翅 |
| 四带二 | `four_two_single` | 4 张同点 + 2 张任意牌（可以是 1 个对子） |
| 四带两对 | `four_two_pair` | 4 张同点 + 2 个不同点数的对子 |
| 炸弹 | `bomb` | 4 张同点 |
| 王炸 | `rocket` | 小王 + 大王（16 + 17） |

### 王与「2」的边界（易错点，已由测试固定）

- **王不能成组**：`16,16`、`17,17`、`16,16,17`、`16,16,16,16` 都不是对子/三张/炸弹，一律非法；只有 `16+17` 是火箭。
- 顺子和连对使用点数 3..A：**不含 2（15）**，也不含王。
- 飞机主体（连续三张）同样只用 3..A；飞机翅膀按下面「飞机翅膀策略」单独判定。
- **四带二 / 四带两对的主体可以是 2**（如 `2222 + 单张 + 单张` 合法，`2222 + 对子 + 对子` 也合法），但主体不能是王——王只有两张，凑不成 4 张同点。
- 顺子、连对、飞机主体的最大点数 ≤ A（14）。

### 飞机翅膀策略（这是本实现书面固定的歧义口径）

- 带单翅：翅膀张数必须恰好等于三张组数 n；同一翅膀点数最多出现 2 次（即一个对子可以拆成两张单翅）；**不能出现 4 张同点**；王只能各算一张（两张王不能凑成「一对单翅」），但 n 张翅膀里可以各含一张王（如 `333444 小王 大王` 合法）。
- 带对翅：每个翅膀必须是一个独立对子（各点数恰好 2 张），点数各不相同，且不能是王。
- 翅膀点数不能与飞机主体的点数重叠（重叠的那些牌已计入主体）。

### 比牌

- 首出（新一轮领出）任意合法牌型均可。
- 跟牌必须 **同牌型 + 同张数** 且主点数更大：主点数指单张/对子/三张的点数，或顺子/连对/飞机的 **最大点数**。
- 炸弹可压任意非炸弹牌型；炸弹之间比点数；火箭压一切。
- 不能过牌的情况：本轮首出（无人出牌）时必须出牌。

### 叫分

- 0 分为「不叫」，1/2/3 分必须严格大于当前最高分；叫 3 分立即成为地主。
- 顺序为座位 0→1→2，每人一次；全部不叫则重新洗牌发牌重新叫分；否则最高叫分者当地主。（托管座位与机器人叫分时，用的是 §2 里那条确定性的本地规则，不是 DouZero 网络，也不会出现「全桌都不叫」的死循环。）
- 地主拿走 3 张底牌，底牌此时公开，并由地主先出。

### 计分（零和）

- 底分 `base = 最终叫分 × 倍数`，倍数初始 1。
- 每出现一次炸弹或火箭，倍数 ×2。
- 春天：地主获胜且两个农民一张牌都没出过，倍数 ×2。反春：农民获胜且地主只出过第一手领出（出牌次数 = 1），倍数 ×2。
- 地主得分 `±2 × base`，每个农民 `∓base`；一局总和为 0。累计分数跨局保留。

### 开始条件

- 三个座位都已入座并准备、且当前房主在线，才能开始；座位可以是真人、房主放好的机器人，或本人开启托管的座位（托管座位即使离线也算就绪）。平板模式由平板房主操作，纯手机模式由当前玩家房主操作。
- 叫分/出牌阶段只要有**没托管**的真人掉线，所有叫分/出牌/过牌都会被拒绝（中文提示「有玩家掉线，等待重连」），重连后自动恢复；托管座位和机器人不受影响，会照常推进本局。

## 4. 掼蛋规则（本仓库固定口径）

### 牌与人数

- 两副牌共 108 张，四人两队：座位 `0`+`2` 与 `1`+`3` 各为一队，每人 27 张。
- 牌点由大到小：大王、小王、级牌、A、K、Q、J、10、9、8、7、6、5、4、3、2 —— **非级牌的 2 永远最小**，级牌比 A 大。
- 每副有一张「级牌」（本副打几点）：同点四张都是级牌，其中**红桃级牌是「逢人配」**，可以当作除大小王之外的任意点数与花色；它不能当王。

### 牌型（10 种）

| 牌型 | kind | 说明 |
|---|---|---|
| 单张 | `single` | 1 张 |
| 对子 | `pair` | 2 张同点 |
| 三张 | `triple` | 3 张同点 |
| 三带二 | `triplePair` | 三张同点 + 1 个对子，两者点数必须不同（五张同点是炸弹，不是三带二） |
| 顺子 | `straight` | 恰好 5 张连续单牌；A 可当 1（`A2345` 最小），最大到 `10JQKA` |
| 同花顺 | `straightFlush` | 恰好 5 张同花色连续单牌 |
| 三连对 | `threePairs` | 恰好 3 个连续对子 |
| 钢板 | `twoTriples` | 恰好 2 个连续三张 |
| 炸弹 | `bomb` | 4–10 张同点（10 张需要两张逢人配补足；级牌炸弹最多 8 张自然牌） |
| 四大天王 | `fourJokers` | 两张大王 + 两张小王 |

### 比牌

- 大小梯度：**四大天王 > 6–10 张炸弹（先比张数再比点数）> 同花顺 > 5 张炸弹 > 4 张炸弹 > 上表七种普通牌型**。炸弹、同花顺、四大天王都能压普通牌型；普通牌型之间只能同牌型同张数对压。
- 顺子、三连对、钢板、同花顺比序列大小（`A2345` 最小）；单张、对子、三张、三带二比点数，级牌按级牌算。
- **不比花色**：点数相同就压不过，「同大」永远不成立。
- 一轮内必须同牌型、同张数才能压；压不过只能过牌。连续过牌清墩后由最后出牌者续出；若他已出完牌，则由其**搭档接风**续出。
- 掼蛋与斗地主共用出牌栏、托管按钮和 SVG 过牌标记。手机牌桌的公共牌区、操作栏和手牌区分别占位；选牌后自动识别最强合法牌型，并显示牌型与配牌说明，不再要求下拉选择。
- 出牌与进贡/还贡的面板、选牌框和操作按钮均为透明背景。握牌与记牌器切换时，角标的位置、尺寸和字体与牌张同步过渡，结束后直接接上目标牌面。
- 平板和两种手机界面共享进贡阶段提示：单贡/双贡、等待还贡、交换完成均有说明；抗贡明确显示哪一家或哪两家合计持有两张大王、本副免进贡及先手。提示在发牌和翻面结束后出现，背景透明。
- 发牌由房间统一节拍：桌面中央的牌背旋转，按座位顺序连续送往 3／4 个方向；手机逐张从屏幕上方接入手牌。斗地主只发 51 张、掼蛋发 108 张，机器人等发牌结束再行动。底牌留在桌面，确定地主后仅在地主手机补入三张；纯手机模式同样发牌和补牌。平板模式的手机在出牌成功后向上送走选牌，纯手机模式不播放出牌动画。重连只续播尚未结束的发牌；减少动态效果、转屏、离开页面均可直接落定手牌。
- 纯手机发牌使用一条连续路径：自己的牌背从牌桌中央平滑移动到手牌槽位，全部到位后统一翻面，机器人和操作控件等翻面结束再继续。公共出牌使用两款游戏共用的独立区域，左右靠边、对家居上、自己居下，长牌型按区域缩放换行，不再受玩家信息框的宽度影响。
- 手机动画使用有上限的临时像素缓存（16 MiB，空闲时预热），静止手牌仍为 SVG。握牌／记牌器切换以一张画布统一绘制牌张与角标；发牌、收牌先批量读取布局，再批量提交轻量画布，避免每张牌重复触发布局和 SVG 阴影滤镜。未变化的牌面在普通状态推送时复用；取消、转屏和离开页面会清理临时动画并恢复手牌。
- 掼蛋可在准备、出牌和进贡/还贡阶段开启或取消自己的托管，默认使用简单 AI（`danzero_v1t`）。开启后自动出牌和交换贡牌，同时关闭手动出牌、过牌及进贡/还贡提交；取消即可恢复手动操作。
- 掼蛋 AI 重放同时核对牌张、牌型、主点数、座位和领出状态，保留每手实际接受的牌型声明，避免把同一组逢人配重读为不同三带二、连张或炸弹；领出状态区分头游搭档先过牌、清墩后再接风的两次轮转。

### 进贡与还贡（由人点选，服务端校验）

- 一副结束后按名次决定谁进贡：进贡的牌必须是手中**最大的牌（红桃级牌除外）**；收贡方还贡必须还**不超过 10 的牌**（整手都大于 10 时还最小牌）。
- 双下（对方两家垫底）时两家各进一张，头游拿较大的那张，另一张给搭档；两张一样大时按「头游下一家进贡」的口径归属。
- **抗贡**：需要进贡的一方合计抓到两张大王，本副不进贡、不还贡，直接由上游先出牌。
- 进贡与还贡都要各家自己提交：**没有全部提交之前牌面不公开，也不进入出牌阶段**，此时任何出牌请求都会被服务端拒绝。
- 多解牌型自动取最强合法解释：同一组牌先按炸弹／同花顺的实际牌力比较，同类再比级牌点数或连张区间；跟牌只从能够严格压过上一手的解释中选择。选牌、滑动出牌、提示和机器人共用同一识别规则，服务端重新校验。例：打 2 时 `QQ + ♣2 + ♦2 + ♥2` 自动识别为 `222QQ`，`♠3 ♠4 ♠5 ♠6 ♥2` 自动补成黑桃 3–7 同花顺。已经接受的历史牌型按原声明精确重放，不重新最大化。

### 升级、过 A 与「再来一场」

- 从打 2 开始（2 也要打，第一副就是打 2）。赢方升级：搭档二游 +3、三游 +2、末游 +1（双下即搭档二游，+3）；升级封顶在 A。
- 打到 A 后，**必须在打 A 的这一副里由已经在 A 的一方拿到头游、且搭档不是末游**，才算过 A 赢得整场；仅仅到达 A 不算过 A。
- 打 A 失败不退级，继续打 A，进贡照常。
- 一副结束后由当前房主开「下一副」；整场分出胜负后房主可以「再来一场」，级数重置回打 2，上一场结果作废。

### 与常见变体的差别（本仓库固定口径）

- 顺子与同花顺固定 5 张、三连对固定 3 对、钢板固定 2 个三张，不随变体伸缩。
- 自然同花顺不降级成普通顺子：一手牌既可按同花顺也可按顺子读时，两种解释都列出，由人选择。
- 炸弹梯度固定为「6 张及以上 > 同花顺 > 5 张 > 4 张」，四王最大。
- 点数相同不比花色，相等的牌压不过上家。
- 打 A 失败留在 A，不存在「打 A 失败退回」的变体。
- 清墩后由搭档接风续出。
- 抗贡按「需要进贡的一方合计两张大王」判定，不要求同一人同时持有。

### 规则依据（实现口径参考，不是官方认证，也不代表最新赛事版）

- 2022 年公开转载的《竞技掼蛋竞赛规则（试行）》：<https://sports.sohu.com/a/621481154_121124679> —— 108 张/每人 27 张、牌型表与「借风出牌」、级数 2..A 与过 A 条件、升级 +3/+2/+1、红桃级牌可代除王以外的任意牌、进贡「红桃级牌除外」的最大牌、还牌不超过 10、抗贡。
- 南京信息工程大学公开的《“掼蛋”比赛规则》：<https://gh.nuist.edu.cn/_upload/article/files/e2/4e/9a5343d0450a9580fd4c1f46fc0b/290d8299-e923-4966-a485-b0269c7e11fd.pdf> —— 四王 > 六张及以上炸弹 > 同花顺 > 五张炸弹 > 四张炸弹 > 其它牌型、顺子「不可超过五张」、三连对「不可超过 3 对」、钢板「不可超过 2 个」、还牌「10 以下（含 10）」、贡牌相同由「头游的下一家先出牌」、打 A 必须一名头游且另一名不为末游、打 A 不过则一直打 A。
- 两份文本并不完全一致（例如双贡两张贡牌同大小时的表述、三带二是否单列），本仓库一律按代码里固定的口径实现；判定逻辑见 `shared/guandan.ts`、`server/games/guandan.ts`，房间与赛制流程见 `server/room.ts`。

## 5. 状态、隐私与边界

- 无账号、登录、数据库或商业化功能；AI 使用本机推理的机器人（斗地主 DouZero、掼蛋 DanLM、国际象棋 Stockfish、中国象棋 Fairy-Stockfish／皮卡鱼），没有任何在线模型调用。
- 房间只在服务端内存中：**重启服务全部清空**；所有已绑定的房主和玩家持续离线 30 分钟后回收，且计时只按**连续空置**计算 —— 房间变空才开始计时，中途任何合法重连都从零重算，不按房间创建时间提前删除。浏览器本地凭证不能恢复已经消失的服务端房间。
- 平板房间是「三或四位玩家 + 一台平板房主」（斗地主 3 人、掼蛋 4 人），纯手机房间就是 3 或 4 位玩家本身；房主身份在内存中，纯手机房主掉线会移交给在线玩家。服务端每 20 秒使用 WebSocket ping/pong 检测失联；前端在前台每 15 秒发起应用心跳，8 秒无回应后重新连接。回到前台和网络恢复时重新同步身份与牌局；心跳不会重发出牌操作。
- 只要还有一个「引擎仍需连接」的座位掉线（斗地主：已入座的三人；掼蛋：进贡/还贡或出牌阶段中手里还有牌的座位），房间就暂停：所有对局指令被拒绝并提示「有玩家掉线，等待重连」，状态栏也照实显示；重连或经房主批准的接替完成后自动恢复。**托管座位与机器人由服务端代打、没有 socket，不算掉线**，不会暂停牌局。
- 机器人座位在公开摘要里只是几个公开事实（`isBot`、`autoPlay`、`botTier`）加一个名字，**不带任何凭证**，也不会拿到手机房主权限；它也没有真 socket，所以不会被当成掉线的真人。托管与机器人出牌走的是同一条服务端权威路径：同一套牌型校验、同一份公开历史与落点、同一次版本广播（同一动作重复发送只会推动一次）。
- 本机凭证按房间、角色、座位保存，并保留标签页身份隔离。只有明确的凭证失效或房间不存在才清理相应凭证；普通断网不删除。旧窗口不能覆盖或删掉另一窗口刚确认的新凭证。
- 同一 token 恢复会绑定原身份，旧连接以关闭码 `4000` 让位。新设备接替必须由房主批准，不能只凭房间号夺取已占座位；接替保留原手牌、积分、位置与回合。
- 同一 action id 不重复执行（房间保留最近 256 个 id）；过期或被替换的连接先验证身份，不能借重放获取手牌。
- `hand` 只含接收者自己的牌；平板的 `hand` 为空。斗地主在地主确定前 `bottom` 为空（掼蛋没有底牌，公开的只有出牌、进贡/还贡结果与级数）。公开房间摘要、链接和接替队列不含 token 或他人私有手牌。
- 所有已入座设备都会收到整局公开的 `tablePlays`，用于公共桌面、手机当前墩与记牌器。`trickStartIndex` 标记当前墩起点；过牌清墩不删除整局历史。
- 历史只记录有效出牌，赢牌在结算前记录。每手的 id 在房间生命周期内不复用（跨副也不重置），落点偏移不超过短边 4.5%、角度偏移 ±8°，由服务端在指令被接受时生成一次，不会因刷新、重连或重复指令而改变。房主重开下一局时清空；发新牌也会清空（斗地主含全部不叫后的重发）。
- 牌面为原创 SVG：数字牌按真实数量排花，J／Q／K 双头人物，大小王和牌背单独绘制。手机握牌使用窄角索引，经典手牌、平板出牌与底牌保留完整角标。

## 6. 端口注意

- 默认端口是 `5180`（`PORT` 环境变量可覆盖）。之所以不用 `5173`：本机上其它开发服务常占用 `5173`，且可能只绑在 IPv6 `[::1]`，导致浏览器访问 `localhost:5173` 时解析到 `::1` 而打开了另一个项目。
- 本服务固定绑定 `0.0.0.0:5180`（IPv4），局域网地址不受 `localhost` 解析差异影响。
- 若 `localhost:5180` 在本机被别的进程占用（`lsof -nP -iTCP:5180 -sTCP:LISTEN` 可确认），改端口即可：`PORT=8081 npm run dev`，手机邀请链接会自动使用新端口（来自 `GET /api/network`）。
- 始终可以用 `http://127.0.0.1:5180` 访问本机服务，绕过任何 `localhost`/`::1` 解析歧义。


## 7. 大厅、常亮与聚会工具

- **手机横屏大厅**：四款游戏按牌类／棋类分区，一屏显示；手机和平板分别布局，不再对长页面等比缩放。禁用页面滚动，竖屏提示旋转；加入入口放进弹层，邀请链接直接打开入座表单。
- **继续游戏**：已有牌局时置于顶部。昵称用于普通开桌；快速练习可使用默认昵称“我”。
- **快速练习**：选择轻松或挑战后，点击游戏卡片上的快速练习，自动创建手机房、补齐机器人、准备并开始。模型不可用或中途失败时保留房间和凭证，并显示实际错误，可改为邀请真人继续。
- **准备页**：房主可“一键用机器人补齐空位”（默认易档），同时明确显示还缺几位玩家、谁离线、谁尚未准备。仍可逐座选择机器人档位。
- **工具 → 常亮**：通过 Screen Wake Lock API 申请屏幕常亮，跨大厅和牌局共享状态。切后台释放，返回前台后重新申请；系统省电等原因释放时显示待恢复，可重试或关闭。普通局域网 HTTP 地址通常无法使用此 API：页面明确提示需要 HTTPS，绝不假报已开启。localhost/127.0.0.1 的可信本机环境可用于开发验证。
- **方向提示**：大厅、斗地主和掼蛋使用横屏，中国象棋和军棋固定竖屏布局；牌类提示增加返回大厅入口；浏览器拒绝全屏后，实际横屏的设备仍可选择继续浏览器横屏。
- **工具 → 查看规则**：两种手机模式与平板均可随时查规则，并显示叫分、进贡或出牌阶段的提示。
- **斗地主即时校验**：与服务端共用纯规则模块 `shared/doudizhu.ts`，选牌即显示牌型或不合法原因；按钮和上滑路径均先校验，服务端仍作最终判定。
- **结算与聚会战绩**：结算显示本局得分、累计分和计算依据（掼蛋显示名次与升级），可逐手查看公开有效出牌并导出 PNG。工具中的战绩保留本浏览器看到的最近 100 副结算，刷新或重启服务后仍可查看；清理浏览器数据后消失。只保存公开结算与已出牌，不保存手牌、token，也不恢复运行中的牌局。

验证边界：自动化测试与浏览器视口模拟不能代替 iOS/Android 真机。常亮、全屏、横屏锁定和网络切换的系统行为仍需在实际使用的设备与地址上验证。
